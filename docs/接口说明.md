# 接口说明

- 服务地址：`http://127.0.0.1:8000`
- 统一前缀：`/api/v1`
- 内容类型：`application/json`；附件上传为 `multipart/form-data`
- 在线调试：`/docs`（Swagger UI）、`/redoc`

## 1. 通用约定

### 1.1 认证

除 `POST /auth/login` 外，所有接口均需携带访问令牌：

```http
Authorization: Bearer <access_token>
```

令牌默认有效期 8 小时，登出后立即撤销；过期、撤销或用户被禁用时返回 `401`。

### 1.2 错误响应

```json
{
  "detail": "错误描述"
}
```

单据提交校验未通过时：

```json
{
  "detail": {
    "message": "单据校验未通过",
    "issues": ["提交前必须至少上传一个附件"]
  }
}
```

常见状态码：`400` 参数/流程不匹配、`401` 未登录或令牌失效、`403` 权限不足、`404` 资源不存在、`409` 状态冲突、`413` 文件过大、`415` 文件类型不支持、`422` 参数校验失败。

### 1.3 权限与数据范围

- `applicant`：本人创建的单据；本人可查看的分析结果。
- `approver`：分配给自己审批任务的单据 + 本人单据。
- `finance` / `admin`：全部单据。
- 规则、市场价、供应商维护：`finance` / `admin`。
- 审批流程配置：`admin`。
- 用户管理：`admin`。

## 3. 单据

### 3.1 创建单据

`POST /documents`

```json
{
  "document_type": "费用报销单",
  "applicant_department": "市场部",
  "budget_department": "市场部",
  "payee_name": "张伟",
  "payee_account": null,
  "expense_category": "办公用品",
  "total_amount": 12999,
  "currency": "CNY",
  "apply_date": "2026-10-21",
  "reason_text": "部门笔记本电脑采购报销",
  "line_items": [
    {
      "item_type": "expense",
      "item_name": "笔记本电脑",
      "item_spec": "ThinkPad X1 Carbon",
      "expense_category": "办公用品",
      "expense_date": "2026-10-19",
      "expense_location": "上海",
      "quantity": 1,
      "unit_price": 12999,
      "amount": 12999
    }
  ]
}
```

`document_type` 枚举：`对公付款单`、`预付款单`、`批量付款单`、`费用报销单`、`差旅报销单`。

类型专属字段（按需传入）：

| 字段 | 适用类型 | 说明 |
| --- | --- | --- |
| `contract_no` / `supplier_name` / `supplier_code` / `payment_ratio` / `payment_terms` / `planned_payment_date` | 对公付款单、预付款单 | 合同与付款条款 |
| `batch_total_amount` / `batch_payment_count` / `planned_payment_date` | 批量付款单 | 批次金额与笔数 |
| `travel_location` / `travel_start_date` / `travel_end_date` | 差旅报销单 | 出差信息 |

响应为完整单据对象（含 `line_items`、`attachments`、`line_items_total`）。

### 3.2 查询单据列表

`GET /documents`

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `document_type` | string | 单据类型 |
| `document_no` | string | 编号模糊匹配 |
| `applicant_id` | int | 申请人 |
| `department` | string | 预算部门 |
| `status` | string | 状态，支持逗号分隔多个 |
| `date_from` / `date_to` | date | 申请日期范围 |
| `keyword` | string | 编号/收款单位/事由模糊匹配 |
| `page` / `page_size` | int | 默认 1 / 10，最大 100 |

响应：

```json
{
  "items": [
    {
      "id": 1,
      "document_no": "GF-202610-0001",
      "document_type": "对公付款单",
      "applicant_name": "张伟",
      "budget_department": "市场部",
      "payee_name": "上海锦程会务服务有限公司",
      "total_amount": 39000,
      "document_status": "approved",
      "attachment_count": 2,
      "risk_level": "low",
      "recommendation": "建议通过",
      "latest_analysis_task_id": 1
    }
  ],
  "total": 5,
  "page": 1,
  "page_size": 10,
  "status_counts": {"draft": 1, "pending_review": 3, "returned": 1}
}
```

### 3.3 单据详情

`GET /documents/{document_id}`

响应在单据字段基础上追加：

- `line_items` / `line_items_total`
- `attachments`（含 `preview_url`、`download_url`）
- `versions`（版本快照列表）
- `status_logs`（状态变化记录）
- `approval`（工作流名称、节点、审批人、意见、时间）
- `latest_task`（最近分析任务）
- `latest_report`（最近成功报告摘要）
- `allowed_actions`（`edit` / `submit` / `withdraw` / `void` / `copy` / `analyze` 等）

### 3.4 编辑单据

`PATCH /documents/{document_id}`

仅 `draft` / `returned` 状态允许编辑；可修改基础字段与类型专属字段，不支持直接修改明细（使用明细接口）。

### 3.5 复制单据

`POST /documents/{document_id}/copy` → 生成新草稿，复制字段、明细与附件文件。

### 3.6 提交审批

`POST /documents/{document_id}/submit`

校验通过后：

1. 递增/生成版本快照；
2. 匹配审批流程并创建审批实例与首节点任务；
3. 创建风险分析任务（后台执行）。

响应：

```json
{
  "document": {"id": 6, "document_no": "BX-202610-0002", "document_status": "pending_review"},
  "approval_instance_id": 6,
  "analysis_task": {
    "id": 7,
    "task_status": "queued",
    "current_step": "queued",
    "progress": 0,
    "document_id": 6
  }
}
```

提交校验项：预算部门、总金额 > 0、付款类收款单位、对公付款合同编号与比例、批量付款笔数、差旅起止日期、至少一个附件。

### 3.7 撤回 / 作废

- `POST /documents/{document_id}/withdraw`：仅申请人、`pending_review` / `reviewing` 且尚无审批处理结果。
- `POST /documents/{document_id}/void`：申请人或管理员，`draft` / `returned` / `withdrawn` / `rejected` 状态。请求体可选 `{"remark": "作废原因"}`。

### 3.8 明细管理

- `POST /documents/{document_id}/line-items`
- `PATCH /documents/{document_id}/line-items/{line_item_id}`
- `DELETE /documents/{document_id}/line-items/{line_item_id}`

明细请求体：

```json
{
  "item_type": "payout",
  "item_name": "上海锦程会务服务有限公司",
  "item_spec": null,
  "expense_category": "批量付款",
  "expense_date": "2026-10-19",
  "expense_location": null,
  "quantity": 1,
  "unit_price": 26000,
  "amount": 26000,
  "payee_name": "上海锦程会务服务有限公司",
  "payee_account": "6222020111002233445",
  "remark": "会务服务尾款"
}
```

`amount` 为空时按 `quantity × unit_price` 计算。

`POST /documents/{document_id}/attachments`

`multipart/form-data`，字段名 `file`。限制：PDF / PNG / JPG，≤ 15MB。响应：

```json
{
  "id": 9,
  "document_id": 6,
  "file_name": "发票.pdf",
  "file_type": "pdf",
  "file_size": 20480,
```

`GET /documents/{document_id}/attachments/{attachment_id}?disposition=inline|attachment`

## 5. 智能审核会话

### 5.1 创建会话

`POST /review-sessions`

```json
{"document_type": "差旅报销单", "document_no": null}
```

响应包含会话信息、`slots` 与欢迎消息。

### 5.2 会话列表

`GET /review-sessions` → 当前用户的会话，含最后一条消息与消息数量。

### 5.3 会话详情 / 历史消息

- `GET /review-sessions/{session_id}`
- `GET /review-sessions/{session_id}/messages`

### 5.4 发送消息

`POST /review-sessions/{session_id}/messages`

```json
{"content": "审核差旅报销单 CL-202610-0001"}
```

响应：

```json
{
  "session_id": 1,
  "messages": [
    {
      "id": 3,
      "role": "assistant",
      "content": "已定位单据 CL-202610-0001（差旅报销单），正在执行附件解析与风险分析。",
      "message_type": "analysis_started",
      "payload": {
        "analysis_task_id": 7,
        "document_id": 3,
        "document_no": "CL-202610-0001",
        "document_type": "差旅报销单"
      }
    }
  ],
  "analysis_task": {"id": 7, "task_status": "queued", "progress": 0},
  "slots": {"document_type": "差旅报销单", "document_no": "CL-202610-0001"}
}
```

`message_type`：`text`、`slot_required`、`analysis_started`、`report`、`error`。

多轮规则：

- 缺少类型 → 询问类型（返回候选列表）；
- 缺少编号 → 询问编号，并给出当前权限内可访问单据；
- 匹配到多张单据 → 返回候选，用户回复序号或编号确认；
- 用户只给编号且能唯一定位 → 自动补全类型；
- 已确认的槽位在会话内保留，不重复询问；
- 单据不存在或无权限 → `error` 消息并允许重新输入。

### 6.4 风险报告

`GET /analysis-tasks/{task_id}/report`

响应包含：

- `summary`：整体等级、等级计数、分类计数、风险评分、Top 风险；

- `amount_comparison`：金额核对结果（单据、明细、发票、合同、付款）；

- `report_markdown`：Markdown 报告全文。

`GET /analysis-tasks/{task_id}/evidence` → 所有风险项证据的扁平列表。

## 7. 人工复核与报告导出

### 7.1 更新风险项复核状态

`PATCH /risk-findings/{finding_id}/review-status`

```json
{"review_status": "confirmed", "comment": "已电话核实发票差额"}
```

`review_status`：`pending`、`confirmed`、`dismissed`。需审批人员/财务/管理员角色。

### 7.2 提交人工复核意见

`POST /review-reports/{report_id}/manual-reviews`

```json
{
  "review_result": "人工复核",
  "review_comment": "住宿费超标，要求补充审批说明"
}
```

`review_result` 枚举：`建议通过`、`补充材料`、`人工复核`、`建议驳回`、`通过`、`退回`、`驳回`。

### 7.3 查询报告列表

`GET /review-reports`

| 参数 | 说明 |
| --- | --- |
| `document_id` | 按单据过滤 |
| `risk_level` | `high` / `medium` / `low` |
| `recommendation` | 处理建议 |
| `has_review` | `true` / `false`，是否已人工复核 |
| `page` / `page_size` | 分页 |

### 7.4 报告详情

`GET /review-reports/{report_id}`

### 7.5 导出报告

`GET /review-reports/{report_id}/export?format=md|html`

返回文件流，`Content-Disposition` 中包含 UTF-8 文件名，如 `风险审核报告_CL-202610-0001_RPT000003.md`。

## 8. 审批

### 8.1 我的审批任务

`GET /approval-tasks?status=pending`

`status` 可选：`pending`、`approved`、`returned`、`rejected`、`cancelled`。

```json
{
  "items": [
    {
      "task_id": 3,
      "task_status": "pending",
      "node_name": "部门负责人审批",
      "document_id": 3,
      "document_no": "CL-202610-0001",
      "document_type": "差旅报销单",
      "applicant_name": "张伟",
      "budget_department": "市场部",
      "total_amount": 4740,
      "document_status": "pending_review",
      "analysis_task_id": 3,
      "risk_level": "medium",
      "recommendation": "人工复核",
      "created_at": "2026-10-21 14:52:33"
    }
  ],
  "counts": {"pending": 2, "approved": 1}
}
```

### 8.2 任务详情

`GET /approval-tasks/{task_id}` → 任务、单据（含审批进度）、分析任务、风险报告摘要、金额核对、风险项列表。

### 8.3 审批操作

- `POST /approval-tasks/{task_id}/approve`　`{"comment": "同意"}`
- `POST /approval-tasks/{task_id}/return`　`{"comment": "请补充发票"}`
- `POST /approval-tasks/{task_id}/reject`　`{"comment": "不符合报销制度"}`

退回与驳回必须填写 `comment`。通过后自动流转到下一节点；最后一个节点通过后单据状态变为 `approved`。

响应：

```json
{
  "task_id": 3,
  "task_status": "approved",
  "instance_status": "running",
  "document_status": "reviewing",
  "node_name": "部门负责人审批",
  "processed_at": "2026-10-21 15:40:00"
}
```

### 8.4 审批流程配置

- `GET /approval-workflows` → 全部流程及节点，按单据类型分组展示。
- `POST /approval-workflows`（管理员）
- `PATCH /approval-workflows/{workflow_id}`（管理员）

```json
{
  "workflow_name": "费用报销标准流程（5000 元以下）",
  "document_type": "费用报销单",
  "match_conditions": {"amount_min": 0, "amount_max": 5000, "departments": ["市场部"]},
  "status": "active",
  "nodes": [
    {"node_name": "部门负责人审批", "node_order": 1, "approver_role": "approver", "approval_mode": "single"},
    {"node_name": "财务复核", "node_order": 2, "approver_role": "finance", "approval_mode": "single"}
  ]
}
```

说明：

- 流程按 `document_type`、`amount_min`、`amount_max`、`departments` 匹配，选择条件最精确者；
- 已被审批实例引用的流程不允许重建节点（可修改名称、条件、状态）；
- 审批角色：`applicant`、`approver`、`finance`、`admin`。

### 9.1 规则列表

## 13. 枚举汇总

### 单据状态 `document_status`

`draft` 草稿、`pending_review` 待审批、`reviewing` 审批中、`returned` 已退回、`approved` 已通过、`rejected` 已驳回、`withdrawn` 已撤回、`voided` 已作废。

### 审批实例状态 `instance_status`

`pending`、`running`、`approved`、`returned`、`rejected`、`cancelled`。

### 审批任务状态 `task_status`

`pending`、`approved`、`returned`、`rejected`、`cancelled`。

### 附件存储状态 `storage_status`

`uploading`、`stored`、`failed`、`archived`（从当前单据移除、保留历史取证文件）。

### 附件解析状态 `parse_status`

`pending`、`parsing`、`succeeded`、`failed`、`manual_review`。

### 风险等级

`low`、`medium`、`high`。

### 风险项复核状态

`pending`、`confirmed`、`dismissed`。

### 处理建议 `recommendation`

`建议通过`、`补充材料`、`人工复核`、`建议驳回`。

## 14. v1.1 版本与并发约束

- `PATCH /documents/{id}` 可一次提交基本字段与完整 `line_items`。编辑页发送读取时的 `revision`；修订号不符返回 `409`，保存后采用响应中的新修订号。
- 提交前必须完成必需附件解析、明细金额核对及该类单据的补充字段校验。草稿、退回、撤回状态可编辑并重新提交。
- 分析任务响应增加 `document_version`。同一版本已有执行中任务时返回现有任务；并发创建冲突返回 `409`，任务保存在数据库中，由固定调度器读取。
- 报告响应增加 `snapshot_status`（`complete` 或 `legacy`）。单据资料与金额来自报告归档；`legacy` 报告会提供历史资料不足提示。
- `GET /documents/{id}/attachments/{attachment_id}/parse-result?task_id={task_id}` 查询指定分析版本保存的识别结果。附件必须属于该任务且用户拥有单据数据权限。
- 所有审批动作必须提交至少2个字的 `comment`。申请人不能自审；通过前须有当前版本最新的完整分析报告。高风险项须处理，并保存有依据的人工复核意见。
- 风险项处理和人工复核仅允许当前审批版本的最新已完成报告。原始风险判断和归档金额保持不变，复核操作追加审计记录。
