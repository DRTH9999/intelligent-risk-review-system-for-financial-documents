# v1.1 完善与验收说明

本次沿用 `app/` 下的 FastAPI、SQLAlchemy 和原生前端，重点修正业务正确性、历史追溯和任务执行。原始《开发文档.md》继续作为需求基线。

## 已落实的行为

| 范围 | 当前行为 |
| --- | --- |
| 输入与金额 | 单据/明细使用 Decimal 输入；拒绝负金额、非正数量、超范围付款比例及不合理日期范围。按分四舍五入计算金额。 |
| 保存 | 编辑页一次保存基本信息与全部明细；修订号过期时返回 409，避免旧页面覆盖新修改。 |
| 提交 | 校验明细合计、数量乘单价、各类单据补充信息、批次笔数与账号、必需附件类型和解析状态。解析未完成时须等待完成后再提交。 |
| 版本 | 每次提交生成新版本；分析任务保存提交版本、输入快照、启用规则参数及其修订信息。 |
| 分析依据 | 将解析结果、历史交易、供应商档案和市场参考价冻结到任务上下文。历史金额比较按币种与申请日期限制范围。 |
| 历史报告 | 页面、接口、列表和导出读取报告归档金额与单据快照，修改新版本不改变旧报告。 |
| 历史附件 | 删除当前附件采用归档方式保留原始文件；报告链接带分析任务编号，展示当时保存的解析结果。 |
| 审批 | 禁止本人审批，分配时跳过申请人；校验实例、节点、版本、角色及任务状态；重复处理返回 409。 |
| 通过条件 | 当前版本的最新分析必须完成；高风险项须处理，并由有权限人员填写有依据的建议通过复核意见。所有通过操作必须填写意见。 |
| 规则 | 停用规则不产生风险项，按适用单据类型加载；配置保存时拒绝未知规则和非法参数。 |
| 任务 | 数据库持久队列、固定调度器、独立工作进程；并发领取只发布一次报告；支持撤回取消、失败重试和超时停止。 |
| 数据权限 | 单据、报告、历史证据及供应商交易记录按当前用户的数据范围访问。 |

## 旧数据升级

服务启动、`scripts/init_db.py` 和 `scripts/seed_demo.py` 都会先执行增量升级。升级现有 SQLite 数据库前，使用 SQLite 的备份接口保存一致性副本到 `data/backups/`，然后增加新字段；不会清空原表或附件。

旧报告没有保存完整分析输入，无法事后准确补造。它们标记为 `legacy`：保留原始报告正文及金额，页面提示历史快照不足。审批中的旧单据可重新分析以生成完整快照报告；历史已结束单据保持归档。

## 开发验证

```powershell
uv sync --group dev
uv run pytest -q
```

测试在操作系统临时目录创建数据库和附件，不使用项目业务数据库。覆盖五类单据的创建、实际 PDF 解析、提交、分析、多节点审批与报告导出，并验证：

- 历史报告与历史识别结果不会因新修改改变。
- 负数、无效比例、明细不符、缺少必需材料、自审及过期编辑被拒绝。
- 停用规则不再生成风险项，任务保留创建时的规则参数。
- 并发分析不会重复发布报告，撤回取消不会重新变成成功。
- 独立工作进程可以执行已入库任务，超时只终止该任务进程。
- 旧数据库升级保留原记录并生成备份。

2026-10-24 验收结果：39 项回归测试通过；全量示例数据重新导入后，6 个分析任务均成功。使用旧业务库的只读备份副本完成增量升级与浏览器验收，验证了登录、编辑保存、旧报告提示、后台重新分析、Markdown 导出和历史附件识别结果查看；浏览器控制台无错误。原业务库未被测试副本覆盖。

## 运行方式与边界

继续使用 `uv run python run.py`。当前采用单机、单个服务进程和一个后台调度器；不要为此配置启用多个 Uvicorn worker。工作进程最大运行时间由 `RISK_REVIEW_TASK_TIMEOUT` 控制，默认 180 秒。排队任务保留在数据库；运行中断或超时的任务显示失败，由用户明确重新分析，已撤回的任务保持取消。

当前“智能”能力是本地 OCR、字段抽取和可解释规则。尚未接入外部大模型、真实发票验真或实时供应商征信。后续工作重点是收集真实且脱敏的多版式材料，衡量字段准确率、误报和漏报，再按实际使用量引入 PostgreSQL、对象存储和独立队列服务。
